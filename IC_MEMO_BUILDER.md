# Claim Trace Inspector

NiveshScope v39 adds a Claim Trace Inspector so the desk can check whether the answer is merely fluent or actually supported by the evidence stack. It sits after IC Memo Builder because committee packets should not move forward when material claims have weak, missing, or synthetic-only support.

## Inputs

The inspector reads only browser-local state:

- The current answer produced by the desk.
- The current Brief Workbench packet, citations, source gaps, and evidence-quality metadata.
- The current IC Memo Builder packet when the user switches the trace scope to `IC memo packet`.
- Source status labels such as REAL, imported, synthetic, or missing.

No external service is called. The static release does not claim perfect natural-language verification; it uses deterministic claim extraction, token overlap, citation metadata, and source-status penalties to expose the claims that deserve human review first.

## Trace Scopes

The scope selector changes which text is inspected:

- `Current answer`: traces the live desk answer plus packet headline and readiness details.
- `IC memo packet`: traces the committee memo text generated by IC Memo Builder.
- `Critical claims`: narrows the list to sentences that mention risk, revenue, margin, cash flow, valuation, debt, capex, deposits, or other material investment terms.
- `Weak claims only`: shows claims that are unsupported, synthetic-backed, or below the support threshold.

## Scoring

Each extracted claim is compared with the current citations. The support score increases when important claim terms overlap with citation terms, when the ticker is aligned, and when the source is REAL or imported. It is penalized when the best available support is synthetic or missing.

The inspector labels claims as:

- `Supported`: enough citation overlap and source quality for review.
- `Review`: partially supported or synthetic-backed, requiring human judgement before use.
- `Unsupported`: no strong citation match, especially risky for critical claims.

Trace quality rolls these labels into one score. Unsupported critical claims are treated as blocking issues for launch and committee circulation.

## Controls

The user can:

- Open the weakest claim.
- Open an individual claim's evidence card.
- Route unsupported claims into the next source gap in Source Pack Studio.
- Copy a Markdown trace note.
- Export a JSON trace pack for audit files or future backend storage.

The routing is deliberately practical: if a citation exists, the evidence card is opened; if no good citation exists, the next source gap for the focused ticker is opened.

## IC Memo And Launch Control

IC Memo Builder includes a Claim Trace section in Markdown and JSON exports. Launch Control includes the claim-trace score in the release score, adds the trace pack to the audit JSON, and creates blockers when unsupported critical claims or SYN-backed claims remain. v40 also feeds the trace score into Answer Quality Lab so weak claim support becomes part of the answer-level QA score.

This matters because a polished PDF is not enough. A research product needs traceability at the claim level before it can be positioned as investment-useful.

## Production Direction

The production version should replace the static heuristic with server-side claim extraction, source-span alignment, immutable citation IDs, reviewer overrides, model-evaluation logs, and audit retention. It should also store every exported trace pack with the report version so future users can see exactly which claims were supported at the time of publication.
